MotionLife — HLD: Pluggable Motion Backend Registry

One VLM router → many specialized extractors → one unified swatch → class-aware apply → VLM judge & auto-tune

Step-by-step — what each stage does (input → output → expect)

The pipeline is a chain of well-defined hand-offs (Contracts A/B/C). Each step is independently testable.

STEP 1

Input

The user uploads a video (any real clip) or types a text prompt. This is the only thing the user has to provide.
In: .mp4 clip, or a text string.
Out: raw media handed to the router.
Expect: works for one clip or a multi-motion clip; text path skips extraction entirely.
STEP 2

VLM Router (classify + decompose)

A vision-language model watches sampled frames and answers: what is moving, how many distinct motions, and each one's class. It picks which backend handles each.
In: sampled video frames (+ artwork for object matching).
Out: Contract A — a list of {object, class, bbox, confidence}.
Expect: a flag+smoke+birds clip returns 3 entries, no filename hints; low-confidence dropped.
STEP 3

Pre-step helpers (D)

Optional refiners the router invokes before extraction: SAM 2 tightens the bbox into a clean mask; Depth Anything adds depth; SLAM/homography separates camera motion from object motion.
In: region bbox + frames.
Out: precise mask / depth map / camera transform.
Expect: tracking runs only on the object, not the background; near objects can move more than far.
STEP 4

Backend extraction (A/B/C/E)

Each detected motion is routed to the right model: skeleton for bodies, flow/point-tracks for texture/fluid, detect+track for object paths, or text-to-motion when there's no video.
In: masked frames + motion class.
Out: raw motion (skeleton seq / flow field / tracks / path).
Expect: real full-clip motion; adding a new backend = one new registry entry, nothing else changes.
STEP 5

Distill → unified Motion Swatch

Whatever the backend produced is normalized into one common swatch schema so the app treats every motion type the same way.
In: backend-specific raw motion.
Out: Contract B — {class, params, tracks?, pose?, bulk, fps}.
Expect: a reusable, editable, scale-free asset that appears in the library like any swatch.
STEP 6

Application (class-keyed)

The applicator branches on the swatch's class, not the layer name: texture→mesh deform, human→skeletal rig, flat character→puppet, object→path travel.
In: swatch + selected artwork object.
Out: the object animating in place.
Expect: right behavior fires from the class; renaming a layer no longer matters (retires name-hardcoding).
STEP 7

Render / Preview

The deformed/transformed artwork is drawn each frame (SVG/Canvas), played back, and can be exported. Frames are also captured for the judge.
In: per-frame transformed artwork.
Out: live animation + N sampled frames + SVG/video export.
Expect: smooth playback; Before/After + source clip in the preview.
STEP 8

VLM Judge

A vision-language model scores the rendered result against the reference clip, lists what's wrong, and proposes parameter deltas.
In: rendered frames + reference + class.
Out: Contract C — {score, issues, suggest:{Δ}}.
Expect: "flag barely moves → +40% intensity"; class-specific rubric (torn flag, sliding water).
STEP 9

Auto-tune loop

The judge's deltas are applied, re-rendered, re-judged — 2–3 iterations or until the score passes. The system corrects its own output.
In: judge deltas.
Out: a tuned swatch that scores above threshold.
Expect: a deliberately weak motion visibly improves and the loop stops on success.
STEP 10

Output

Final animated artwork — exported as animated SVG or video — with the original artwork preserved pixel-for-pixel and the swatch reusable on other objects.
In: tuned, playing scene.
Out: exported animation + saved swatches.
Expect: nothing redrawn; the same swatch re-applies to any compatible object.
